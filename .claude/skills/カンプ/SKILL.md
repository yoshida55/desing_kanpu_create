# カンプ スキル

`data/camps/*.html` を直すときに繰り返し使う編集パターンをまとめたスキル。
パターンは今後どんどん追加していく前提（1個から始める）。

## 使い方
```
/カンプ
```

## Step 0. まず種類を聞く（必ず最初にやる・TodoWriteは不要）

以下の選択肢を出して、ユーザーに選んでもらう。

- **A. 演出の順番づけ**（画像→見出し→マーカー→ヘッダー、のように表示順とタイミングをずらす）

- **C. 部品を別の場所・別カンプへ運ぶ（📌パレット）**
- （今後ここに増える）

どれにも当てはまらないことを言われたら、無理に当てはめず「わからないので教えてください」と素直に聞く。

## A. 演出の順番づけ

### 目的
複数の要素（画像・見出し・マーカー・ヘッダー等）を「①→②→③…」の順番で、それぞれ好きな遅れ時間(ms)で表示させる。ボタン式の「グループ」機能は微調整が難しく不採用になった経緯があるので、**数値は会話で聞きながら直接編集する**（UIをいじらせない）。

### 使う仕組み（このツール固有・必ず覚えておく）

- 要素に `data-cedelay="ミリ秒"` を付けると、その要素の出現アニメ(`fxa_pre`)またはマーカー(`fxa_hl`)が、その時間だけ待ってから再生される。
- `fxa_pre` の出現方向は class で決まる：`fxa_y`(縦)/`fxa_xl`(左から)/`fxa_xr`(右から)/`fxa_s`(拡大縮小)/`fxa_bl`(ぼかし)/`fxa_ry`(回転)など。
  - `--fxa-dist` は普通は正の数（下・横からのズレ幅）。**マイナスにすると逆方向から出てくる**（例：`fxa_y` に `--fxa-dist:-42px` を指定すると「上から降ってくる」動きになる）。
  - 文字を1文字ずつ出す見出し（`fxa_cpre`）は、`--fxa-stag`(1文字ごとの間隔) と `--fxa-dur`(1文字分の所要時間) を持つ。トータルの所要時間は概算で「(文字数-1)×`--fxa-stag` + `--fxa-dur`」。
- マーカー（`.fxa_hl`、蛍光ペンで引いた帯）は `--hldur`(伸びる秒数)・`--hlt0`/`--hlt1`(帯の上下位置%)・`--hlw`(再生位置、常に`0`で初期化しておく)を持つ。
- ⚠️**罠**：昔は`data-cedelay`を知らない古い保険スクリプト（`src/viewer.py`の`_SERVE_SAFETY`）が先にfxa_inを付けてしまい、狙った遅延が無視されて即表示になるバグがあった（2026-07-05修正済み）。作業前に念のため次を確認する：
  ```
  grep -n "data-cedelay" src/viewer.py
  ```
  ここで`_SERVE_SAFETY`（`fxaStart`関数）側にも`data-cedelay`の分岐が出てくることを確認してから進める。出てこなければ先に直す。

### 手順

1. 対象のカンプHTML（`data/camps/*.html`、直近で編集しているファイルを`ls -t`等で特定）を確認し、演出したい要素（画像・見出し・マーカー・ヘッダー等）を特定する。
2. ユーザーに希望の順番と大まかな感覚（速い/遅い、どの方向から）を聞く。曖昧なら遠慮せず聞く。
3. 各要素の`data-cedelay`(ms)を、前の要素の「開始時刻＋そのアニメの所要時間」を目安に計算する。
4. 対象要素の`data-cedelay`属性・`class`・`--fxa-dist`等をEdit/正規表現で直接書き換える（ユーザーにUI操作をさせない）。
5. 「サーバー再起動（起動.bat開き直し）→ブラウザ再読み込みで確認してください」と伝える。
6. 「もっと速く/遅く」「まだ早い/遅い」等のフィードバックが来たら、該当する`data-cedelay`・`--fxa-dur`・`--hldur`の数値だけを直接調整する（ボタンUIには誘導しない）。

## B. 留めた背景（sticky）が下まで透ける／隙間が白い

### 目的
🏞で留めた写真の帯が、ページの下の方でも繰り返し見えてしまうのを止める。あるいは逆に、見せたい所だけ透けさせる。

### 使う仕組み（このツール固有・必ず覚えておく）
- 留めた帯は `position:sticky; top:0; z-index:-1`。**親の下端まで貼りつき続ける**ので、後ろのセクションが透明な場所すべてで透けて見える。＝穴は1つではなく何個も出る。
- 見えている所の一覧は 右クリック →🎨セクションの背景色 →🔎留めた写真が見えている所。要素・すき間・いちばん下の余り の3種類を出す。
- ⛔ここまで＝帯とその手前を素の `div`（`data-ceovwrap`）に入れて、留まる範囲をそこで終わらせる。sticky は親の下端で必ず終わるので、これが唯一の確実な止め方。
- 塞ぐ手段は3つ：要素＝背景色（`data-ceovbg`）／すき間＝下の要素の `box-shadow` を上へ伸ばす（`data-ceovsh`）／余り＝最後の要素の影を下へ伸ばす（`data-ceovtail`）。**すき間はマージンで誰の背景でもないので、要素を塗っても埋まらない**。

### ★順番を間違えない（今回いちばんの教訓）
```
✅ 正しい: ⛔で留める範囲を決める → 中の見せたい所だけ透けさせる
❌ 逆順  : 透けさせる → 出てきた穴を塞ぐ → また出る（無限ループ）
```

### 手順
1. **測ってから直す**。`venv/Scripts/python.exe` + playwright で `/camp_preview/<file>` を開き、帯の `offsetTop`/`offsetHeight`、各セクションの `backgroundColor`、すき間を実測する。
   - ⚠**位置は `offsetTop` で測る**。`getBoundingClientRect` は sticky が貼りついた今の位置を返すので、すき間の計算が全部狂う（6005px のような嘘の値が出る）。
2. 一覧（🔎）を開き、見せたい範囲の**次**のセクションで **⛔ここまで** を押す。
3. 範囲の中で、透けさせたいセクションを「透けさせる」に戻す。
4. 隙間が白く残るときは、帯を高くして隙間ごと覆うほうが早い（塞ぐと白いままになる）。
5. 一覧が「透けている所はありません」になったら完了。区切りは「区切りを解除する」でいつでも戻せる。

### 触ると危険
- 後続セクションに `position:relative` を足さない（中の絶対配置の基準が変わって潰れる）。背景色を敷くのは配置に影響しないので安全。
- マスク（🫧一部だけ透明）を `article`/`main`/`body` に掛けない。**ページ丸ごとが薄くなり**、症状は「関係ないセクションが白い」に見えるので原因にたどり着けない。
- 背景色を変えても見た目が変わらない時は、相手に背景画像が乗っている（帯そのものを選んでいることが多い）。

## C. 部品を別の場所・別カンプへ運ぶ（📌パレット）

### 目的
見出し＋本文のブロックなどを、別の場所や別のカンプへ持っていく。

### 使う仕組み
- 📌パレットは中身を localStorage にHTML文字列で持つ＝**再起動しても残る／別カンプでも使える**。
- 入れる：右クリック →📌パレットに入れる → 板の ⬆外側へ広げる / ⬇内側へ狭める で範囲を合わせる（対象が緑の点線で光る）→ 📋残す or ✂消す。
- 置く：カードの ✥そのまま置く（箱ごと）／✥中身だけ置く（外の箱を外す＝狭い所に入る）。ドラッグ中に緑の線で挿入位置が見える。
- スライドショーを含む部品は、置いた直後に自動で動き直す。

### ★限界（先に伝える）
クローン由来のカンプは**中身が全部 `position:absolute`** で、見た目の並びとDOMの親子が一致していない。そのため：
- ✅ 運べる：DOM的にまとまっている塊（カード・セクション）
- ❌ 運べない：見た目で隣り合っているだけの寄せ集め（拾っても足りない・置くと飛ぶ）
- 範囲でまとめて運びたくなったら、**運ばずにその場で作り直す**ほうが速い（🏞帯・📝文字セット・🔶図形は自由配置前提なので崩れない）

## 共通の心得（全パターン）

1. **推測で直さない。まず実測**（playwrightで computed値・offsetTop を見る）。見た目バグを目視で追うと往復が増える。
2. **「まだ残っている」が2回続いたら、対症療法をやめて原因の構造を断つ**。同じ症状が繰り返すのは、原因が1つで対処が的外れなサイン。
3. **1つ試すごとに💾保存**。未保存で長く進めると「どこまで戻すか」が判断できなくなる（🔄開き直す＝保存済みの状態に戻る）。
4. **サーバ側（viewer.py）を直したら、起動.bat再起動＋ページ再読み込み**。片方だけだと古い挙動のままで「直したのに直っていない」と誤認する。
