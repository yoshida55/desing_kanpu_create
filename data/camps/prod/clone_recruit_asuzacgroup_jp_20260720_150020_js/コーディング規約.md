### HTML構造とスタイルの分離
・HTMLは、意味と構造が分かるクラスだけで組む。セクション名を先頭にした `section_inner` / `section_head` / `section_list` / `section_item` など、役割が分かる命名にする
・インラインの `style` 属性は使用しない。レイアウト・余白・色・サイズ・アニメーションはすべてCSSファイルに記述する
・JSで利用しない `data-*` 属性、空要素、不要なラッパー要素は作らない。必要な要素だけで浅い階層にする
・画像・見出し・本文など、意味のある要素は残し、装飾だけの要素はCSSの疑似要素で表現できるか検討する
・見た目の調整はHTMLに書き戻さず、対応するセクションのCSSにまとめる
・実装・修正後は、不要な属性や要素が残っていないか確認し、Playwrightで表示を確認してから報告する


### JSの目印（data-* / id / class の使い分け）
・JSが要素を「つかむ力」は id・class・data-* で全く同じ（data-* が掴むのが得意なわけではない）
・data-* の値打ちは“掴む性能”ではなく「JS専用の印だと一目で分かる＋CSS(見た目)やリンク(#)の用途と混ざらない」こと
・**一番大事なのは「1方式に統一して混ぜないこと」**（このサイトは data-* に寄せる方針）
　❌ data-*・素のクラス・js_クラスが混在 → 読む人が迷う
　✅ JSの目印は data-* に統一 → 「これはJSが動かす部品」と一目で伝わる

・**見た目用のクラスをJSの目印に流用しない**
　⇀ class名で掴むと、デザインでclass名を変えた時にJSが連動して壊れる。data-* なら壊れない
　⇀ id で掴むと、その id が #リンクのジャンプ先にも使われていると役割が二重で紛らわしい

・存在チェック `if (要素) { … }` は付ける（無くても落ちない保険）
　⇀ 「画面に来たら」ではなく「その要素が存在するか」の確認
　⇀ JSはエラーが出ると**以降の処理が全部止まる**ので、1個の欠けで他機能まで巻き添えにしないため

```html
<!-- HTML：JSが動かす部品の印は data-* -->
<button class="btn" data-menu>メニュー</button>
```
```js
// JS：data-* でつかんで → 動かす（class ".btn" でも掴めるが、見た目変更で壊れる）
const menu = document.querySelector("[data-menu]");
if (menu) {                       // 存在チェック＝保険
  menu.addEventListener("click", () => {
    document.body.classList.toggle("is_menu_open");
  });
}
```

### コンテナ幅（中央寄せ枠）の指定
・`.inner` など中央寄せ枠の幅は「上限で頭打ち＋狭い画面では縮む」を基本にする
・固定幅（`width: 126rem` 等）は使わない → 狭い画面で**はみ出す**（横スクロールの原因）
・`max-width: Xrem; width: 100%;` と `width: min(Xrem, 100%);` は**完全に同じ意味**。
⇀なので⇀`max-width: Xrem; width: 100%;`で統一！

・どちらも `margin: 0 auto;` で中央寄せする

```css
/* 余白いらない：上限で頭打ちして画面いっぱいに縮む */
.inner {
  max-width: 126rem;   /* width: min(126rem, 100%); でも同義 */
  width: 100%;
  margin: 0 auto;
}
```

↓隙間を作る場合、上記とは意味が違う
[プレビュー](http://localhost:54321html_20260629_204815_461.html)


```css
/* 狭い画面でも左右に余白を残したいとき：calc で枠側にスキマを作る */
.inner {
  width: min(126rem, calc(100% - 8rem)); /* 8rem＝左右合計の余白。左右4remずつ残る */
  margin: 0 auto;
}
```

・狭い画面の左右余白は `calc(100% - 〇rem)` か、親の `padding-inline` のどちらかで作る（二重に付けない）

padding-inlineとは・・・padding-left: 4rem;padding-right: 4rem;
↓
padding-inline: 4rem;   /* 左も右も4rem */

### line-height / letter-spacing（em変換と使い分け）

#### 基本の計算式（line-height も letter-spacing も共通）
・カンプの値 ÷ フォントサイズ ＝ em
・⚠ 単位は px にそろえて割る（`font-size: 1.9rem` は 19 で割る。1.9 で割ると10倍ズレる）
・例：letter-spacing 7.6px ÷ 19px = 0.4em ／ line-height 35 ÷ 19 = 1.842em

#### letter-spacing の「÷1000」は数字（トラッキング値）のときだけ
・カンプの値が「数字（単位なしのトラッキング・XDなど）」→ ÷1000
・カンプの値が「px（Figmaなど）」→ ÷フォントサイズ
　（px を ÷1000 すると字間がほぼ0になりカンプと食い違う）

#### line-height を「書く / 書かない」の線引き
・複数行になるテキスト（本文・説明文など）→ line-height を書く（カンプ値 ÷ フォントサイズ）
・1行で収まるテキスト → line-height は書かない
　※「書かない」＝0ではない。reset.css の `line-height: 1.5` を継承する点に注意
・例外①：特大の見出し（タイトルなど）→ 1行でも `line-height: 1em` を書く
　理由：1.5を継承すると行の箱が文字より大きくなり、文字が下にはみ出して次の要素とくっつくため
・例外②：同じクラスを「1行」と「複数行」で共有している場合 → 1行側でも line-height は書く（外さない）
　理由：複数行の方が line-height を必要とするため。1行だけのために外すと複数行が崩れる
　チェック：1行だからと機械的に外す前に「そのクラスが複数行でも使われていないか」を必ず確認する
　例：.content_text に「住宅設備•修理（1行）」と「太陽光発電•蓄電池•オール電化（2行）」が同居 → line-height を書く

```css
/* 複数行テキスト：行間を指定 */
.modal_row_text {
  line-height: 1.667em; /* 25 ÷ 15 = 1.667 */
}

/* 1行テキスト：line-height は書かない（1.5を継承） */
.staff_name {
  font-size: 3rem;
}

/* 特大見出し：1行だが1.5継承だとはみ出すので例外で1 */
.staff_title {
  line-height: 1em;
}

/* 同じクラスで1行と2行が混在：複数行が必要なので line-height は書く */
.content_text {
  line-height: 1.44em; /* 36 ÷ 25 = 1.44（2行の「太陽光…オール電化」に必要） */
}
```

#### ⚠ PCで付けた letter-spacing / line-height はスマホに残る（カスケード）
・メディアクエリは「書いたプロパティだけ上書き」する。書かないとPCの値がスマホでもそのまま効く
・PCで付けた値が、スマホのカンプでは 0（または別の値）のとき → スマホ側で明示的に打ち消す／上書きする
　- 0 に戻す → `letter-spacing: normal;`（または `0`）
　- 別の値 → その値で上書き
・⚠「親要素からの継承」ではなく「同じセレクタのPC用ルールが残っている（カスケード）」のが原因
・チェック：レビュー時「PCで付けた値がスマホに漏れていないか」を必ず確認する

```css
/* PC */
.modal_name_en {
  letter-spacing: 0.2em; /* 3 ÷ 15 = 0.2 */
}

@media screen and (max-width: 767px) {
  /* スマホはカンプ0 → PCの0.2emを打ち消す */
  .modal_name_en {
    letter-spacing: normal;
  }
}
```
