## 0.0.-3.6 🐛絵文字×文字系アニメで💾保存が必ず失敗するバグ根治（2026-07-20）

- **症状**：「走る下線を付けてアニメをつけ直したら下線が消えた」報告の正体。
  絵文字入り見出し（🍀等）に文字系アニメ（一文字ずつ/タイプライター/波打ち）を付けると、
  splitCharsが絵文字をサロゲートペアの真ん中で2分割→💾保存が
  「⚠失敗：'utf-8' codec can't encode character（surrogates not allowed）」で**確実に落ちる**
  →保存できないままリロード＝下線も⏳順番も全部消える。実カンプで再現・修正・検証済み。
- **修正**（viewer.py・3点）：①splitCharsをサロゲートペア＋VS16（絵文字飾り指定）対応＝絵文字は1箱で分割
  ②cleanHtmlの保存直前に孤立サロゲートだけ除去する保険（正常な絵文字は残る）
  ③保存版フォールバック（fxaStart）が`fxa_ud`（走る下線）を知らず--hlw:0のままだった穴も同時に修正。
- Playwrightで通し検証済み：下線→タイプライター適用→保存成功→開き直しで下線が走る（--hlw:0→100）。
  なお「アニメつけ直し」自体は下線を壊さない（in-session・保存・再生とも正常を実測確認）。

  さらに**画像は幅も%**（画面と一緒に伸縮）・**文字は折り返し解禁＋置いた位置から右端までのmax-width**＝

  織り込んでからリセット（残すと狭い画面で再びはみ出す＝実測で発見）。
  ⚠運用注意：**普段のデスクトップ幅で開いて保存し直す**と意図した位置で%化される（狭い幅で保存すると
  「その幅での見た目」基準で変換される）。カンプ自身のCSSが非レスポンシブな箇所（固定幅ギャラリー等）は
  別問題＝AI修正で個別対応。

## 0.0 ヘッダー/フッターの部品化（2026-07-11・新機能）

⭐セクションお気に入り／🔀入れ替えを **`<header>`/`<footer>` にも拡張**（AIなし＝無料）。
①「どこを直す？」に「🧢 ヘッダー」「🦶 フッター」が出る（そのタグがあるカンプのみ）。
- **kind属性**（section/header/footer）で部品を区別し、🔀は同じ種類だけ表示（枠違い事故防止）。
  ヘッダー/フッターはAI修正・改善案の対象外（サーバーの差し替えが`<section>`限定の正規表現のため）＝ガード済み。
- **CSSの持ち運び＝`partCss()`**（viewer.py）：計算済みスタイル丸埋めは崩れて不採用（min-height:auto→0px化等）。
  代わりに「その部品に実際に効いているCSSルールだけ」を全シートから抽出し、`<style data-cepart>`として
  部品自身に抱かせ、**@scope**でその部品の中だけに効かせる（レスポンシブ・:hoverも生きる）。
  ★@scopeの罠2つ（実測）：内側のセレクタは暗黙で「:scopeの子孫」＝①ルート自身(.hero{})にも
  ②ルートを先祖に使う形(.hero .nav{})にも素のままでは効かない → **:scopeへ書き換えたコピーも同梱**。
  :hover等は保存時に誰にも当たらない → 疑似部分を外して判定。@keyframesは@scopeの外に置く。
- **護身用`:scope{position:relative;z-index:1}`**（元がstaticの部品のみ）：入れ替え先に
  「親にrelativeが無い絶対配置（.hero-media等が画面基準で浮く）」があると部品に被さる実害があった。
- **🔀直後の表示**：差し替えた新要素にはIntersectionObserverが付いておらずfxa_pre等が透明のまま
  永久に出ない → 差し替え時にfxa_in/SHOWクラス/--hlw:100を機械付与（💾保存時にcleanHtmlが素へ戻す＝
  開き直せば普通に再生）。
- **_index.jsonの排他制御**（camp.py）：削除の同時実行でindexが壊れる事故が実際に起きた →
  ロック＋tmp→os.replaceの安全書き込みに変更（save_camp_htmlと同じ方式）。並列3保存3削除でテスト済み。
- ⚠既知の限界：入れ替え先に**同名クラスの疑似要素content**（例 `.hero-copy::before{content:"…"}`）が
  あると、その飾り文字が部品内に混入する（クラス名衝突）。根治はクラス名の名前空間化＝将来課題。

### ⑤ 保存・配信まわりのバグ修正3件（総点検で発見）
1. **保存版の保険（`_REVIEW_FALLBACK`）に隠しメニューガードが無かった**：

   本家FX_RUN不在時にマーカーが`--hlw:0`のまま＝一生引かれない。`--hlw:100`で少なくとも表示するよう修正。

## 0.5 直近の大改修（2026-07-05）＝カンプの「演出タイミング」を作り込み＋バグ退治

この日は、右クリック編集バーの**アニメ/マーカー系のかゆい所**を直しつつ、
**「要素をどの順番・何秒後に出すか」を自由に指定できる仕組み**（`data-cedelay`）を追加した。
あわせて、保存・配信まわりに潜んでいた地味なバグを何本も退治した（詳細は7章にも記録）。

### ① 右クリック＝即ドラッグONを廃止（文字選択との衝突を解消）
- 右クリックすると自動でドラッグモードになる仕様だったが、これが**文字をドラッグ選択して
  下線/マーカー/文字色を付ける機能と衝突**していた（選択のmousedownがドラッグに奪われる）。
- 右クリックだけでは動かせないようにし、「🖱 掴んで動かす」ボタン（メニュー最上部に移動）／
  **Altキー+ドラッグ**（新規・ボタンを押さず即つかめる）で動かす方式に統一。
- ★2026-07-06に再反転：Altを毎回押すのが手間という声を受け、**普通にクリック＋ドラッグ＝即つかんで動かす**を既定に戻した。
  代わりに「文字を選んで下線/マーカー/文字色を付ける」操作だけを**Alt+ドラッグ**に割り当てた
  （Alt無しだとドラッグが選択より先に割り込むため）。`html.__ce_altmode`のカーソルも`move`→`text`に変更
  （Alt中＝選択モードの合図）。

### ② 🖍マーカーの太さ・速さを調整可能に＋再生方式を作り直し
- 選択ポップアップ／右クリックメニューに「太さ」「速さ」ボタンを追加（`fxHlThick`/`fxHlSpeed`）。
- ★CSSの`transition`を付け外しして再生し直す方式は環境によって不安定 →
  **`--hlw`(0〜100)をrAFで毎フレーム手動更新する方式**に変更（`sweepHl`／`window.__fxaSweepHl`）。
  連打対策に世代番号(`__hlGen`)で古いループを自動停止。
- 帯の位置もデフォルトを文字の下寄り（70%〜92%）に調整。

### ③ 「演出の順番づけ」＝`data-cedelay`を新設
- 要素に`data-cedelay="ミリ秒"`を付けると、その要素の出現(`fxa_pre`)またはマーカー(`fxa_hl`)が
  指定時間だけ待ってから再生される。
- ボタン式の「グループ(`data-cegrp`)」機能も先に作ったが、微調整が難しく
  **会話でミリ秒を直接指定する運用**に落ち着いた（`.claude/skills/カンプ/SKILL.md`の
  「A. 演出の順番づけ」に手順化済み）。
- ⚠**罠**：配信時にfxa_pre要素を強制表示する古い保険（`_SERVE_SAFETY`の`fxaStart`）が
  `data-cedelay`を知らずに先に表示してしまうバグがあった→両方が同じルールに従うよう修正済み。

### ④ 動きを消すボタン／保存まわりの地雷を除去
- 「🚫 この要素の動きを消す」ボタンを追加（`removeBake`）＝焼き込んだ出現/ループ/文字アニメを
  素の状態に戻せる。
- **保存(`cleanHtml`)の抜け穴を2つ発見・修正**：
  1. ブラウザ拡張機能(Glasp)がページに注入したUI断片が保存のたびに紛れ込み増殖
     （1ファイルで708個・223KB→84KB相当の肥大化）→ 保存時に自動除去するよう修正。
  2. マーカーが伸びきった状態(`--hlw:100`)で保存すると、次回開いた時にアニメせず
     「最初から引かれた状態」になる → 保存時に`--hlw`を必ず0へリセットするよう修正。

### ✅ ⑳ ✏文字編集パネルが勝手に閉じて書きかけが消える → 解決（2026-07-21）
- **原因2つ**：①`#__ce_pk`系パネルは**暗幕（箱の外）クリック＝閉じる**仕様で、textareaのリサイズや
  文字選択で手が箱の外に出ただけで閉じていた ②タイトル(h4)を掴んで動かして**箱の外で手を離すと
  clickの対象が暗幕になり**「暗幕クリック」に化けて閉じていた（＝動かしただけで消える）。
- **対処**：①**文字編集パネルだけ**暗幕クリックで閉じないようにした（閉じるのは × だけ・案内文も追記）
  ②ドラッグ直後の暗幕clickをキャプチャ段階で握りつぶす（`_pkDragged`・**全パネル共通**で効く）。
  他パネルの「暗幕クリックで閉じる」は今までどおり（退行なしを実測確認）。

### ✅ ㉑ 「見えているのに右クリックで掴めない絵」→ 解決（2026-07-21）
- **原因**：その絵に `pointer-events:none`（クリックがすり抜ける設定）が付いていた。
  `document.elementsFromPoint` は **pointer-events:none の要素を返さない**ので、右クリックしても
  後ろの器が選ばれる＝一生掴めない。🎯重なり選択も同じAPIを使っていたので**一覧にすら出なかった**
  （コメントには「pointer-events:noneの飾りも拾える」と書いてあったが実際は拾えていなかった）。
- **対処**（viewer.py）：`_peNoneAt(x,y)`＝矩形の当たり判定で「すり抜ける絵」を拾う関数を新設
  （IMG/SVG/CANVAS/VIDEO/PICTURE と背景画像持ちだけ・小さい順・画面6割超の膜は除外）。
  ①クイックメニュー先頭に **🫥「クリックがすり抜ける絵があります」**行を出し、押すと
  `pointer-events:auto` に戻して掴めるようにする（ホバーで赤枠プレビュー付き）
  ②🎯重なり選択の一覧にも混ぜる（🫥マーク付き）。
- ★**自動で掴み替える実装は捨てた**：最初「器を掴んだら小さい絵を優先」で作ったが、
  文字の上を右クリックした時に飾りが横取りする誤爆が実測で出た（7か所中4か所）。
  **見えない挙動より、明示的に選ばせるUIの方が安全**。
- ⚠**画像の中の一部分（例：PNGに描かれた黄色い気球）は掴めない**のが正しい。画像の中身はHTMLに
  存在しないピクセルの塊なので、できるのは「画像まるごとの移動・削除・差し替え」まで。
- ★**さらに続き**：実際の「消せない気球」の正体は`<img>`ですらなく**疑似要素で描かれた絵**だった
  （`DIV.lcl-about__in::before` が130×130のPNGを背景に敷いている）。要素が存在しないので🫥でも
  🎯でも掴めない＝➖「見えている飾りを消す」でしか消せない。しかし一覧の表示が
  「ここ：飾り(::before)」だけでは**どれが気球か人間には絶対に分からない**ため、
  **疑似要素が背景画像を持つ場合はボタンにサムネイルと寸法を出す**ようにした（`decoScan`の`img`）。
  ＝目で見て選べる。クローンサイトの飾りは疑似要素で絵を敷く実装が多いので効果が大きい。

### 📏 余白を詰める（新機能・2026-07-21・AIなし）
- **背景**：「親を選んで高さを縮める」がうまくいかない、という報告。原因は**`min-height`**。
  生成カンプのセクションはほぼ全部 `min-height:720px(100vh)` ＋ `padding:120px 0` を持っており、
  `height` をいくら縮めても min-height に負ける＝**永久に詰まらない**。手で戦うのは無理筋だった。
- **実装**（viewer.py `padInfo`/`padTarget`/`padTighten`/`padShrink`/`padReset`）：右クリックすると
  自分＋外側4段から「一番ムダが大きい箱」を選び、**数字で原因を名指し**して出す。
  例：`📏 ムダな余白が 461px あります／高さ720px ／ 中身259px ／ 最小の高さ720px が効いています`
  ボタン＝**⬍中身の高さまで詰める**（min-height:0+height:auto＝本命）／**▁上下の余白を半分**（連打可）／
  **⟲元に戻す**（インライン指定を消すだけ＝完全復元）。中身が空の箱には**🗑箱ごと消す**も出す。

### 🕳 ドラッグで空いた「穴」を埋める（新機能・2026-07-21・AIなし）
- **背景**：📏を作った後も「余白が消せない」報告が続いた。真犯人は余白ではなく**ドラッグ移動の跡**。
  ドラッグは `translate`＝**見た目だけ**動かすので、元いた場所にその要素の高さぶんの空白が残る。
  padding も min-height も持っていない空白なので、📏で何度押しても1pxも縮まない。
  実例：`section.sd` が `data-cety="-925"` で上に925px移動 → 下に925pxの白い穴。
- **実装**（viewer.py `dragHoles`/`dragBake`/`dragUnbake`/`_holeUnpin`）：ページ全体を走査して
  ズレたブロックを一覧表示（ホバーで赤枠）→「🕳穴を埋める（見た目はそのまま）」で
  **translateの縦ぶんを margin-top に振り替える**＋⟲で完全復元（`data-cehole`に元の値を保存）。
- ★踏んだ罠3つ（全部実測で発見）：
  1. **対象を絞らないと大事故**：最初は全要素を拾って13個をmarginに振り替え→translateと違い
     marginは**兄弟を押し出す**ので別セクションが68pxズレた。→ **縦に1列で並ぶ箱
     （section/header/footer・main直下）だけ**に限定。小さい飾りや文字は対象外。
  2. **横(tx)は振り替えない**：margin-left は幅が変わって見た目が動く。translateのまま残す。
  3. **`main` の min-height が焼き付いていると穴を閉じてもページが縮まない**（実例10278px）。
     → `_holeUnpin`で入れ物系（section以外）の最小の高さだけ外す。section等は📏の仕事なので触らない。
- 実測：ページ 10991px → 9963px（−1028px）。動かしたセクション自身の位置は不変、下の7セクションだけ上がる。
- ⚠**クローンカンプは `transition:all` を持っていることがあり**、marginを書いた瞬間にアニメして
  位置がふらつく（ブラウザペインでは永久に反映されない）。→ 振り替えの一瞬だけ`transition:none`にする。

### ✅ ㉒ 数字を編集すると小さい文字になる（✏文字を編集がタグを消していた）→ 解決（2026-07-21）
