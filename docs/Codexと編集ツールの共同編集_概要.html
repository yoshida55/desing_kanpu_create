Visual editor × Codex

同じページを、壊さず交互に編集する仕組み

編集ツールは正式なHTMLを保存し、CodexはそのHTMLを直接書き換えずに 「どこを、どう直すか」というパッチを作ります。次にツールで開いたとき、 パッチが先に反映されるため、そのまま編集を続けられます。

● 現在は仕様段階・機能は未実装 ● 完成後はコピー運用不要
結論：対象は同じページ。ただし、ツールとCodexが同じHTMLを同時に直接書き換えるわけではありません。

処理の流れ

1

ツールで編集・保存

ユーザーが要素を移動し、文字や画像を変更します。正式なキャンプHTMLへ保存します。

→
2

Codexがパッチを作る

安定IDで対象を確認し、位置・余白・文字・画像などの安全な変更だけを別ファイルへ記録します。

→
3

ツールで再び開く

編集機能が始まる前にパッチを適用します。ツールからは、修正済みの通常要素として見えます。

→
4

確認・再編集・正式保存

ユーザーがさらに編集できます。保存成功後、変更をHTMLへ統合し、パッチは消化済みにします。

↻ 必要なだけ「ツール → Codex → ツール」を繰り返す

どのファイルを使うのか

① 正式なキャンプHTML

ツールが保存する本体。

最終的な正本は一つだけです。コピーを本番として並行管理しません。

② Codexパッチ

Codexが作る一時的な変更指示。

data/camp_patches/*.patch.json を想定。ツール保存後は消化済みになります。

③ codex_test

以前の試作用コピー。

本番の共同編集では使いません。パッチ機能が完成するまでの参考資料にすぎません。

ツールとCodexの役割

担当 行うこと 行わないこと
編集ツール HTMLの表示、選択、移動、編集、パッチの取込み、正式保存 世代が古いHTMLやパッチを強制上書きしない
Codex 対象IDを確認し、検証済みの位置・文字・画像・装飾パッチを作成 本番HTMLの直接書換え、任意のdiv追加・削除、編集用属性の破壊
ユーザー ツールとCodexを交互に使い、結果を確認して正式保存 同じページをツールとCodexで同時進行させない

安全に往復するための約束

できること

  • 位置・大きさ・余白・文字組みを整える
  • 色・背景・枠線・角丸・影を調整する
  • 文字や画像を安全な方法で差し替える
  • ツールで再編集し、同じHTMLへ正式保存する

初期版ではしないこと

  • Codexによる本番HTMLの直接編集
  • 任意のdiv追加・削除・親子関係の変更
  • innerHTML やスクリプトの自由挿入
  • 競合を無視した強制上書き

同時編集は避ける

「ツールで保存 → Codexがパッチ作成 → ツールで確認・保存」の順で進めます。 念のため世代の不一致もシステム側で検出し、変更を失う可能性がある保存は停止します。

現在と完成後の違い

現在 共同編集機能の完成後
Codexの修正 試作コピーでの確認が中心 同じ対象ページ用の安全なパッチを作成
codex_test 過去の試作・参考 本番運用では不要
ツールへ戻る 直接変更したHTMLでは動作保証なし パッチ反映後も選択・移動・保存可能
競合時 運用で避ける ハッシュとrevisionで検出し、安全に停止

このHTMLは概要資料です。実装の細かな条件、例外、テスト項目はMarkdown仕様書を正とします。
